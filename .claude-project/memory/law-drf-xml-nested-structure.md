법제처 DRF (`lawService.do`) `target=law` / `target=lawjosub` 응답 구조:

```
<법령 법령키="...">
  <기본정보>
    <법령ID>...</법령ID>
    <법령명_한글>...</법령명_한글>
    <법종구분 법종구분코드="A0002">법률</법종구분>
    <소관부처 소관부처코드="...">법무부</소관부처>
    <시행일자>...</시행일자>
    ...
  </기본정보>
  <조문>
    <조문단위 조문키="0276001">
      <조문번호>276</조문번호>
      <조문여부>조문</조문여부>  <!-- 또는 "전문" -->
      <조문제목>...</조문제목>
      <조문내용>제276조(...)</조문내용>
      <항>
        <항번호>① </항번호>
        <항내용>① 본문...</항내용>
        <호>
          <호번호>1.</호번호>
          <호내용>...</호내용>
          <목>
            <목번호>가.</목번호>
            <목내용>...</목내용>
          </목>
        </호>
      </항>
    </조문단위>
  </조문>
</법령>
```

**파싱 규칙**:
- 메타데이터는 루트 직속 X, `기본정보` 자식에 위치
- 본문은 `조문 > 조문단위[]` 배열, `조문여부 === "조문"`만 본문 (전문/章 제외)
- XML 속성 (`@_법종구분코드`) + 텍스트 노드 (`#text`) 동시 처리 — `str()` 헬퍼는 `#text`만 처리하므로 속성은 별도 추출
- 항/호/목은 각 본문에 마커가 이미 포함 (`<항내용>① 본문...`) — 항번호 + 항내용 결합 시 중복 방지 필요

**Why:** lawjosub 응답이 루트 직속에서 평면 구조라 가정한 기존 파서가 모든 본문 빈 문자열 반환. 라이브 호출로만 발견 가능.

**How to apply:** 법령/조항호목 detail 파서 작성 시 `root.기본정보` 자식에서 메타, `root.조문.조문단위[]` 배열에서 본문. 속성 노드는 별도 access. 본문에 마커 포함 여부 확인 후 prefix 처리.
